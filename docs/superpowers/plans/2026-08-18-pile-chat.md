**Goal:** Give notes a lifecycle and a way to be found, listed, cleared and promoted to chores, entirely from Campfire.

**Architecture:** `items` gains a `state` column. The chore-shaped prompt/line machinery is generalised so a numbered line can point at either a chore or an item, which is what lets `done 2` work against a search result. A `!` prefix carries the new commands, because every bare word is a capture and a keyword would eat thoughts.

**Tech Stack:** Go 1.23+, pgx v5, Postgres. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-08-18-pile-design.md`

## Global Constraints

- **Postgres is never on the capture path.** Raw text is spooled, fsynced and acknowledged before any parsing. Nothing in this plan runs during capture.
- **Capture is the default.** An intent matches only if the ENTIRE trimmed message is one of its forms. When in doubt, capture.
- **`.` is the escape hatch and wins over everything**, including `!`.
- **No counts.** Nothing may emit a total of open notes. A capped list says *that* there is more, never *how much* more. This includes log lines and error messages.
- **No new dependencies.** Ask before adding one.
- **Every state transition is reversible**, and a repeated identical transition is a no-op, not an error — a tap is a state assertion.
- **Small commits**, conventional-commit subjects, lowercase imperative.
- **Mutation proof required.** Every test must be proven to fail against reverted production code, and the report must quote the assertion failure. A compile error is not proof.
- Integration tests need `TEST_DATABASE_URL=postgres://squirrel:squirrel@127.0.0.1:55432/squirrel_test` and the `//go:build integration` tag. Store-touching tests go in tagged files.

```sql
-- 0008_item_state.sql
--
-- items had no state at all: a note was raw text and a timestamp, permanently,
-- and the evening message showed it exactly once. This is the exit.
--
-- Four states, and `kept` is the load-bearing one: a serial number or a link is
-- not a task and will never be `done`, so with only done/dropped every
-- reference note would sit in triage forever and rebuild the pile inside the
-- thing meant to clear it.
--
-- Every existing row becomes 'open', which is true — nothing has ever been
-- triaged.
alter table items add column state text not null default 'open';

-- Null until the first transition. `received_at` says when the thought
-- arrived; this says when it was dealt with, and the two are different
-- questions.
alter table items add column state_at timestamptz;

alter table items add constraint items_state_known
  check (state in ('open', 'done', 'dropped', 'kept'));

-- The pile query is "open, newest first". The search query is unindexed on
-- purpose: it is a substring scan over one person's rows, run by hand, a few
-- times a day.
create index items_state_received_idx on items (state, received_at desc);
```

```go
// notes.go

package squirrel

// ItemState is what a note has become. `open` is the pile; the other three are
// exits. Every transition reverses, including back to open — undo is a
// transition, not a special case.
type ItemState string

const (
	ItemOpen    ItemState = "open"
	ItemDone    ItemState = "done"
	ItemDropped ItemState = "dropped"
	ItemKept    ItemState = "kept"
)

// SetItemState moves a note. Writing the state it already holds is a no-op
// rather than an error: a tap is a state assertion, and a redelivered webhook
// is byte-identical to a second tap.
func (s *Store) SetItemState(ctx context.Context, itemID int64, state ItemState, at time.Time) error {
	if _, err := s.pool.Exec(ctx, `
		update items set state = $2, state_at = $3 where id = $1`,
		itemID, string(state), at); err != nil {
		return fmt.Errorf("setting item state: %w", err)
	}
	return nil
}

// OpenItems is the pile: untriaged notes, newest first.
//
// It returns at most limit rows and a bare boolean saying whether more exist.
// Deliberately not a count — a number that grows while you are not looking,
// beside an implied target of zero, is the streak mechanism this project bans.
// The caller cannot render a total it was never given.
func (s *Store) OpenItems(ctx context.Context, personID int64, limit int) ([]Item, bool, error) {
	return s.itemsWhere(ctx, `person_id = $1 and state = 'open'`, limit, personID)
}

// SearchItems matches raw text across every state, newest first. `kept` exists
// precisely so a reference note leaves triage and stays findable, so filtering
// by state here would defeat the state.
func (s *Store) SearchItems(ctx context.Context, personID int64, query string, limit int) ([]Item, bool, error) {
	return s.itemsWhere(ctx, `person_id = $1 and raw_text ilike '%' || $2 || '%'`, limit, personID, query)
}

// itemsWhere asks for one row more than the caller wanted, so "is there more"
// costs no second query and never needs a count(*).
func (s *Store) itemsWhere(ctx context.Context, where string, limit int, args ...any) ([]Item, bool, error) {
	q := `select id, raw_text, received_at from items where ` + where +
		` order by received_at desc limit $` + strconv.Itoa(len(args)+1)

	rows, err := s.pool.Query(ctx, q, append(args, limit+1)...)
	if err != nil {
		return nil, false, fmt.Errorf("listing items: %w", err)
	}
	defer rows.Close()

	var items []Item
	for rows.Next() {
		var it Item
		if err := rows.Scan(&it.ID, &it.RawText, &it.ReceivedAt); err != nil {
			return nil, false, fmt.Errorf("scanning item: %w", err)
		}
		items = append(items, it)
	}
	if err := rows.Err(); err != nil {
		return nil, false, fmt.Errorf("listing items: %w", err)
	}

	more := len(items) > limit
	if more {
		items = items[:limit]
	}
	return items, more, nil
}
```

`Item` may not carry an `ID` field today. If it does not, add one and populate it in the drain — check `capture.go` and `drain.go` first, and keep the change minimal.

```go
// LineRef is what a numbered line points at. Exactly one field is set, and the
// database enforces that rather than trusting every caller to remember.
type LineRef struct {
	ChoreID *int64
	ItemID  *int64
}

// Line is a resolved numbered line. Exactly one of Chore and Item is non-nil,
// which is why callers switch on nil rather than on a kind string: the
// compiler cannot check a string.
type Line struct {
	Position int
	Chore    *Chore
	Item     *Item
}

// RecordPromptLines is RecordPrompt generalised. RecordPrompt remains as the
// chore-shaped wrapper because roughly twenty call sites pass []Chore and
// changing them all would put the risk of this migration in every one of them.
func (s *Store) RecordPromptLines(ctx context.Context, personID int64, conversationID, kind string, sentAt time.Time, forDate *time.Time, lines []LineRef) (int64, error) {
	// body is today's RecordPrompt, with the insert loop changed to:
	//
	//   insert into prompt_lines (prompt_id, position, chore_id, item_id)
	//   values ($1, $2, $3, $4)
	//
	// passing l.ChoreID and l.ItemID straight through as nullable values.
}

func (s *Store) RecordPrompt(ctx context.Context, personID int64, conversationID, kind string, sentAt time.Time, forDate *time.Time, chores []Chore) (int64, error) {
	lines := make([]LineRef, 0, len(chores))
	for _, c := range chores {
		lines = append(lines, LineRef{ChoreID: &c.ID})
	}
	return s.RecordPromptLines(ctx, personID, conversationID, kind, sentAt, forDate, lines)
}
```

`&c.ID` inside a range loop is safe here: `go.mod` says `go 1.26.6`, and since 1.22 each iteration gets its own `c`. On an older directive this would alias every line to the last chore.

`LineAtPosition` mirrors `ChoreAtPosition`'s existing query — same "most recent numbered prompt for this person" subquery, same `numberedKinds` filter — but joins both `chores` and `items` with left joins and fills whichever came back.

`numberedKinds` gains the two new kinds:

```go
const numberedKinds = `('digest', 'query', 'nudge', 'notes', 'find')`
```

**Read the phase 4 ledger entry on `numberedKinds` before changing it.** Adding `'evening'` there once made a zero-line prompt shadow the morning's nudge, so the chore became unmarkable by tap, by `done`, and by `done 1`. `notes` and `find` are safe for a different reason than they look: they are undated (`sent_for_date` nil), so they cannot collide in the once-a-day unique index, and they are *meant* to shadow an older numbered surface — the newest numbering wins, exactly as `query` already does. Say this in the comment.

`ChoreAtPosition` keeps working and keeps its signature; give it `and pl.chore_id is not null` so a note line does not make it return a zero `Chore`.

```go
// `!` is a prefix rather than a keyword, and that is load-bearing. Every bare
// word is a capture by design, so a keyword-triggered command would eat
// "find my keys" and "notes to self". Phase 2 hit the same trap with
// `every day i think about leaving`, and the answer is the same: make the
// command shape unambiguous rather than guess at intent.
//
// An unknown command is still IntentCommand, not a capture. A typo answered
// with 👀 would be silently filed as a note, and the correction with it.
if after, found := strings.CutPrefix(trimmed, "!"); found {
	name, arg, _ := strings.Cut(strings.TrimSpace(after), " ")
	if name == "" {
		// A bare "!" is not a command; it is something someone typed.
		return Intent{Kind: IntentCapture, Text: trimmed}
	}
	return Intent{
		Kind:    IntentCommand,
		Command: strings.ToLower(name),
		Arg:     strings.TrimSpace(arg),
	}
}
```

```go
// NotesMessage renders the pile.
//
// `more` is a boolean, so this function cannot render a total even if a later
// author wanted one: the number never reaches it. That is the no-counting rule
// enforced by the shape of the call rather than by a comment.
func NotesMessage(items []Item, more bool) Message {
	if len(items) == 0 {
		return Message{Text: "Nothing in the pile."}
	}
	var b strings.Builder
	for i, it := range items {
		fmt.Fprintf(&b, " %d. %s\n", i+1, it.RawText)

	}
	return Message{Text: strings.TrimRight(b.String(), "\n")}
}
```
